# Планирование бюджета

Личный бюджет-трекер Полины: дневной лимит на жизнь, история трат, хотелки, список покупок и долгосрочный план накоплений в евро. Одна страница, открывается с телефона как ярлык на домашнем экране.

- Сайт: https://skalunova.github.io/Saver/me/ — эта ветка `me`. По адресу https://skalunova.github.io/Saver/ — пустой шаблон из `main`.
- Ветки: `me` — версия Полины с её планом и данными; `main` — шаблон с настройками в интерфейсе, без личных данных. Правки для Полины — в `me`; в `main` только то, что нужно шаблону. Кнопка «Бэкап» есть только в `me`.
- Деплой: `.github/workflows/pages.yml` (одинаковый в обеих ветках). Пуш в `main` собирает сайт из обеих веток; пуш в `me` перезапускает эту сборку на `main`. В настройках Pages источник — GitHub Actions.
- Раньше в этом репозитории жила «Кубышка» (трекер накоплений в рублях, localStorage `kubyshka_v2`). Она заменена этой страницей; её 24 хотелки перенесены в евро.

## Как работать

- Отвечать по-русски, начинать с «Полина, …». Только суть: без вступлений и без предложений помощи в конце.
- Уточняющий вопрос — только как весь ответ целиком, не довеском к готовому.
- Простое решение для простой задачи. Никаких фреймворков, сборки, бэкенда без прямой просьбы.
- Не трогать несвязанный код; замеченные проблемы называть отдельной строкой с файлом и местом.
- Неуверенность называть прямо. Компромиссы — коротко: что получаем, чем платим.
- Тексты в интерфейсе — инфостиль, 1–2 слова в названиях, суммы только в евро.

## Файлы

- `index.html` — вся страница: разметка, стили, шим хранилища, основной IIFE-скрипт и скрипт бэкапа. Шрифт Roboto с Google Fonts.
- `data.json` — последний бэкап базы, публикуется рядом со страницей. Обновляется кнопкой «Бэкап».
- `CLAUDE.md` — этот файл.

## Хранилище

Страница написана под базу артефакта Claude (`window.claude.use('db')`). В этой версии перед основным скриптом стоит шим с тем же интерфейсом поверх `localStorage`:

- ключ `budget-db-v1` — вся база одним JSON;
- при первом открытии (ключа нет) база берётся из `data.json` рядом со страницей, без сети — из константы `SEED` в шиме (снимок на 06.10.2026);
- интерфейс: `db.doc('коллекция/id').set|update|delete`, `db.collection('имя').onSnapshot(cb)`, где `cb` получает `{docs:[{id, data()}]}`.

Следствия: данные живут в одном браузере, между устройствами не синхронизируются; очистка данных сайта возвращает последний бэкап из `data.json`. Изменение `SEED` не доходит до тех, у кого база уже создана, — для этого нужна смена ключа или миграция.

Прочие ключи `localStorage`: `kopilka-done` (галочки старого графика, больше не используются), `kopilka-fold2` (свёрнутые блоки), `kopilka-tab` (открытая вкладка), `saver-gh-token` (токен GitHub для бэкапа), `saver-backup-at` (время последнего бэкапа).

Шаблон из `main` живёт на том же домене и использует свои ключи (`saver-db-v1` и др.), поэтому базу Полины не видит.

### Бэкап

Кнопка «Бэкап» в подвале страницы (видна на обеих вкладках) коммитит базу из `budget-db-v1` в `data.json` ветки `me` через GitHub API. Токен — fine-grained, только репозиторий `Skalunova/Saver`, Contents: read and write; вводится один раз и хранится в `localStorage`. При ответе 401/403 токен стирается и запрашивается заново. Если данные не изменились, коммита нет.

### Коллекции

| Коллекция | id | Поля |
|---|---|---|
| `spend` | `YYYY-MM-DD` | `amount` — сумма за день, `items: [{a, n}]` — сумма и пометка |
| `wishes` | `b01…b24` из Кубышки, `c<timestamp>` новые | `name`, `price`, `done`, `day` — дата покупки; появляется при отметке, `null` после снятия, в `SEED` нет |
| `extra` | `x<timestamp>` новые, `x20260928a`, `x20260928b` в `SEED` | `date`, `amount`, `cur: 'RUB'\|'EUR'`, `note` |
| `paid` | `data-p` строки долга (`done`; `del: true` — строка удалена: скрыта в таблице и истории, её платёж убран из плана, сумма вернулась в копилку): `fee-260925`, `friend-260928`, `dorm-261005`, `dep-261005`, `d3-261005`, `d3-261105`, `d3-261205`, `olya-261205`, `fee-270205`, `fee-270805`, `fee-280205` | `done` |
| `debts` | `c<timestamp>` | `name`, `amount` — строка из поля ввода, не число (в план идёт через `money()`, рубли по `RUB`), `date`, `done` — платежи, добавленные вручную |
| `shop` | `s<timestamp>` | `name`, `done`, `t` |

Дата в id `paid` не всегда равна дате платежа: `d3-261005` — платёж 13.10, `fee-270205` — 13.02.27, `dorm-261005` оплачен 28.09. Дата платежа — в `data-d` строки таблицы, по ней оплаченная строка попадает в историю трат. Id не переименовывать: по ним хранятся галочки, после переименования они сбросятся.

## Структура страницы

Две вкладки, переключение через `main[data-tab]` и `section[data-tab]`.

- **Каждый день:** `#today` «Траты на жизнь» (счётчик и плитки), `#hist` «История трат», `#shop` «Список покупок» (свёрнут), `#wish` «Хотелки» (свёрнут).

В «Истории трат» сверху форма добавления траты (`#bf`), под ней «Итого за всё время», дальше месяцы от старых к новым. Месяц — сворачиваемая группа с итогом в заголовке; прошедшие месяцы свёрнуты, текущий и будущие раскрыты, ручное раскрытие помнится до перезагрузки (`mOpen`). Внутреннего скролла у блока нет.
- **Долгосрок:** `#next` «Детализация периода», `#xin` «Поступления», `#rules` «Правило», `#debts` «Обязательные платежи», `#plan` «График по датам» — всё, кроме первого, свёрнуто.

Блоки сворачиваются по заголовку (`.tg`, класс `collapsed`, умолчание из `data-closed`).

Основные функции: `build()` — собирает события плана и считает копилку; `renderNext()`, `renderPlan()`, `renderBud()`, `renderWishes()`; `addSpend(day, delta, note)`.

## Логика плана

Константы в скрипте:

- `L = 23` — лимит на жизнь, €/день.
- `RUB = 105.5` — курс для доп. поступлений в рублях; плановая зарплата посчитана по 105.
- `START = 22.09.2026`.
- `COVER = 122` — покрытый перерасход, прибавляется к доступному.
- `MOVE = {'2026-10-02': 589, '2026-10-05': 89}` — покупки для переезда, идут в историю, но не в дневной лимит.

Ритм поступлений:

- **13-е** — зарплата, плановая 1545 €. Из неё: долги и взносы, жизнь на 15 дней (345 €), остаток в копилку.
- **28-е** — аванс 1264 €. Из него: аренда 330 €, жизнь до 13-го, остаток в копилку.
- **15-е** — выплата с блок-счёта 992 € до сентября 2027; премия 15-го в январе, апреле, июле, октябре.

Правило в интерфейсе читается в порядке «сколько придёт → сколько в копилку → остальное на жизнь».

Платежи, добавленные вручную в «Обязательные платежи» (`debts`), идут в план: списываются с последнего поступления «на жизнь» не позже своей даты (раньше первого — с первого). Если ему не хватает, нехватку закрывают поступления без жизни в том же периоде (блок-счёт, премия) — строкой «закрыть нехватку», как доп. поступления; в детализации это «Доплата из поступлений».

Долги и взносы в плане:

- долг 150 000 ₽ частями: 13.10, 13.11 по 476 €, 13.12 — 477 €;
- Оле 175 € — 13.12;
- семестровый взнос TUHH 400 € — 13.02.27, 13.08.27, 13.02.28.

Доп. поступление сначала закрывает недостачу предыдущего события (`need`), остаток идёт в копилку.

Доступно на сегодня = дни периода × `L` + `COVER` − все траты периода, включая записанные на будущие даты.

«Ушло за день» (`dayOut()`) — всё, что видно в истории трат: записи `spend`, покупки для переезда `MOVE`, оплаченные строки долгов (рубли переводятся по `RUB`). На этом считаются:

- в истории трат — итог в заголовке каждого месяца и «Итого за всё время» над списком;
- в графике — периоды. Период начинается с поступления, у которого есть строка «на жизнь» (13-е и 28-е), и длится до следующего такого же; поступления без неё (15-е, поступления из `extra`) входят в текущий период, первый период начинается с `START`. Заголовок периода — даты и итог «в копилку − не хватает»; по нажатию раскрывается, раскрыт только текущий период, остальные свёрнуты (`pOpen`, до перезагрузки). Внутри: «Поступления» и «Расходы» построчно с датой (строки «закрыть нехватку» не показываются — это перенос внутри плана), «В копилку» или «Не хватает», затем «по истории потрачено» за дни периода, «баланс» = поступления − потрачено без переноса и «в копилке» на конец периода. Суммы вида «остаток 624 + аванс 460» уже включают прошлый остаток — так задумано.

Контрольные точки при последней сверке: копилка 12 899 € на 13.02.2027, 64 547 € на сентябрь 2028. После правок плана сверять с ними или объяснять расхождение.

## Открытые вопросы

- Зарплата 13.10 может прийти меньше плановых ~511 €.
- Блок-счёт ещё не разблокирован, 15-е — условная дата.

## Решено, не трогать

- 589 € за 02.10 «покупки для переезда» остаются оценкой, уточнять не нужно.
- Трата 01.10 на 155 € остаётся одной строкой без пометок.

## Проверка перед коммитом

Открыть `index.html` в браузере шириной 390 px: нет ошибок в консоли, на «Каждый день» видны счётчик и история, новая запись переживает перезагрузку. Вёрстка проверяется на телефонной ширине — таблицы не должны вылезать за экран.

Репозиторий публичный: суммы, долги и имена видны всем. Новые личные данные в код и `SEED` — только с согласия Полины.

## Дизайн

Дизайн-система v2 (по референсам Cleo, Minna no Ginko, Kit): сейчас внедрена на вкладке «Каждый день», «Долгосрок» пока на прежних правилах (общие у них только токены, шрифт, вкладки, кнопки, поля и карточки).

- Шрифт Golos Text. Роли: `.big-n` — главная сумма экрана 64/800 с единицей 22/700; `.mid-n` — сумма блока 36/800 с единицей 18/600 (формат «331 /345 €»); h1 30/800; h2 20/800; текст 15/400; подпись `.lbl` 14 muted; шильдик `.tag` 12/700. Крупные цифры — плотный трекинг −0.04em, табличные.
- Цвет: тёплый фон `--bg`, белые карточки без рамки (радиус 24), главный блок экрана — цветной `--hero` («Траты на жизнь»). Управление — тёмные пилюли (`--ink`), поля — заливка `--field`. Статус — шильдиками `.tag` (`t-ok` в норме / по карману, `t-warn` выше нормы, `t-grey` нейтрально), а не цветом текста.
- Итоги внутри карточки — строка с точечным лидером `.lead` («Расходы за сегодня ……… 0 €»).
- Вкладки — переключатель: дорожка-пилюля и тёмный бегунок, который едет за `main[data-tab]`.
- Форма траты: «сумма» и «на что» — одинаковые поля с подчёркиванием без заливки; дата — пилюля «сегодня ▾» (`#bdl`), поверх неё прозрачный `input[type=date]` `#bd`; рядом `#bdv` «за день N €», если выбран не сегодняшний день.
- «Траты на жизнь»: два равноценных блока, всё по центру. «Можно» — 76/800, высотой примерно до верхней трети подковы; сумма в подкове — 43/800, под дугой с зазором, не касается её концов. Слева «Можно сегодня» и сумма. Справа «Потрачено из N €» (N — лимит периода), подкова над суммой, заполнена долей потраченного от лимита. Ниже лидеры: «Потрачено сегодня», (если 0) «Снова можно с …», «Расходы до dd.mm» с шильдиком темпа: «высокие» (`t-warn`, потрачено больше нормы на сегодня = прошедшие дни периода × `L`), «низкие» (`t-ok`, меньше 80 % нормы), иначе «норм» (`t-grey`). Порог 80 % — допущение, не согласован.
- Палитра (выбрана Полиной): светлая — белый, `#EDECF3`, голубой `#B7D8F1` (главный блок), персиковый `#EFC5B7` (шильдик-предупреждение), чёрный; тёмная — чёрный, синий `#124476` (главный блок), розовый `#E86C6C` (подкова и предупреждение), `#EDECF3`, белый. Карточки в тёмной — `#111115` (производный оттенок, в палитре его нет). Шильдики: `t-ok`, `t-warn`, `t-grey`.
- Чекбоксы списков — свои (квадрат 24, радиус 8, тёмная заливка при отметке). Хотелка не по карману — серый шильдик и неактивная галочка.
- Токены и роли — в `:root` и блоке «Дизайн-система v2» в конце `<style>`; новых размеров и цветов не заводить.
- Сетка: шаг 4 px. Внутри блока отступ 16, между элементами 12, строки списков 8 по вертикали, вложенные строки сдвинуты на 12.
- Подложка только у сворачиваемых блоков (`.panel`). На «Каждом дне» разделителей нет, кроме линий между месяцами истории. Все блоки по умолчанию свёрнуты (`data-closed`), раскрытия помнятся в `kopilka-fold3`.
- «Траты на жизнь»: плитка периода — потрачено крупно (красным, если больше нормы на сегодня = прошедшие дни периода × `L`), мелко — «из N €».
- «Детализация периода»: под суммой поступления подпись «поступит <дата> · через N дн.». «Обязательные траты» — итог и под ним напоминание: дата, название (из таблицы «Обязательные платежи»), сумма, оплаченные зачёркнуты. Затем «Жизнь N дней», «Остаток на период». Ниже — «До <дата> оплатить»: неоплаченные платежи текущего периода с датой от сегодня.
- Хотелки: галочка «купила», цена 0 € вместо «даром»; галочка недоступна, пока хотелка не по карману.
- Платёжные строки удаляются через × с подтверждением.
