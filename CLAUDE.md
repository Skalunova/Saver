# Планирование бюджета — шаблон

Бюджет-трекер на одной странице: дневной лимит на жизнь, история трат, хотелки, список покупок и план накоплений в евро. Открывается с телефона как ярлык на домашнем экране. Ветка `main` — пустой шаблон, все суммы и даты задаются в интерфейсе.

- Сайт: https://skalunova.github.io/Saver/ — шаблон из `main`.
- Ветки: `main` — шаблон без личных данных; `me` — версия Полины с её планом, данными и кнопкой «Бэкап», сайт https://skalunova.github.io/Saver/me/. Правки для Полины — в `me`, её `CLAUDE.md` там. В `main` только то, что нужно шаблону.
- Деплой: `.github/workflows/pages.yml` (одинаковый в обеих ветках). Пуш в `main` собирает сайт из обеих веток; пуш в `me` перезапускает эту сборку на `main`. В настройках Pages источник — GitHub Actions.

## Как работать

- Отвечать по-русски, начинать с «Полина, …». Только суть: без вступлений и без предложений помощи в конце.
- Уточняющий вопрос — только как весь ответ целиком, не довеском к готовому.
- Простое решение для простой задачи. Никаких фреймворков, сборки, бэкенда без прямой просьбы.
- Не трогать несвязанный код; замеченные проблемы называть отдельной строкой с файлом и местом.
- Неуверенность называть прямо. Компромиссы — коротко: что получаем, чем платим.
- Тексты в интерфейсе — инфостиль, 1–2 слова в названиях, суммы только в евро.
- Личных данных в `main` нет и не должно быть: ни в коде, ни в `SEED`.

## Файлы

- `index.html` — вся страница: разметка, стили, шим хранилища и один IIFE-скрипт. Шрифт Roboto с Google Fonts.
- `.github/workflows/pages.yml` — деплой.
- `CLAUDE.md` — этот файл.

## Хранилище

Страница написана под базу артефакта Claude (`window.claude.use('db')`). Перед основным скриптом стоит шим с тем же интерфейсом поверх `localStorage`:

- ключ `saver-db-v1` — вся база одним JSON, `SEED` пустой;
- интерфейс: `db.doc('коллекция/id').set|update|delete`, `db.collection('имя').onSnapshot(cb)`, где `cb` получает `{docs:[{id, data()}]}`.

Данные живут в одном браузере. Прочие ключи: `saver-fold` (свёрнутые блоки), `saver-tab` (вкладка). Версия Полины на том же домене использует ключи `budget-db-v1` и `kopilka-*`; шаблон их не читает и не трогает — пересекаться ключам нельзя.

### Коллекции

| Коллекция | id | Поля |
|---|---|---|
| `cfg` | `main` | `start` — дата старта, `limit` — €/день, `horizon` — горизонт плана, мес. (1–60). Создаётся с умолчаниями при первом открытии |
| `inc` | `i<timestamp>` | `name`, `amount`, `day` — число месяца, `months` — список 1–12 или пустой (каждый месяц), `until` — дата или `''`, `life` — оплачивает ли жизнь |
| `rec` | `r<timestamp>` | `name`, `amount`, `day` — регулярный расход каждый месяц |
| `debts` | `c<timestamp>` | `name`, `amount` — число, `date`, `done` |
| `extra` | `x<timestamp>` | `date`, `amount` (€), `note` |
| `spend` | `YYYY-MM-DD` | `amount` — сумма за день, `items: [{a, n}]` — сумма и пометка |
| `wishes` | `c<timestamp>` | `name`, `price`, `done`, `day` — дата покупки |
| `shop` | `s<timestamp>` | `name`, `done`, `t` |

## Логика

`build()` раскладывает поступления из `inc` по месяцам от `start` на `horizon` месяцев (число больше длины месяца сдвигается на последний день).

- Поступление с `life` оплачивает лимит × дни до следующего поступления с `life` (у последнего — месяц вперёд).
- Регулярные расходы и платежи из `debts` списываются с последнего поступления с `life` не позже их даты; если такого нет — с первого. Если поступлений с `life` нет вообще, берутся все поступления.
- Остаток идёт в копилку; если не хватает — `need`, «добрать». Нехватку сначала закрывают поступления без `life` в том же периоде (строка «закрыть нехватку»; в детализации — «Доплата из поступлений»).
- Доп. поступление сначала закрывает `need` предыдущего события, остаток — в копилку.

Дневной бюджет: доступно = дни со `start` × `limit` − траты с `start`, включая записанные на будущие даты. Период для плитки «Лимит» — между поступлениями с `life`, без них — календарный месяц. Оплаченные платежи попадают в историю трат по своей дате.

«Ушло за день» (`dayOut()`) — записи `spend` плюс оплаченные платежи из `debts`. На этом считаются «Итого за <месяц>» и «Итого за всё время» в истории трат и низ карточек графика.

График — периоды. Период начинается с поступления с `life` и длится до следующего такого же; остальные поступления входят в текущий период, первый период начинается со `start`. Заголовок — даты и итог «в копилку − не хватает», по нажатию раскрывается; прошедшие периоды свёрнуты (`pOpen`, до перезагрузки). Внутри: «Поступления» и «Расходы» построчно с датой (строки «закрыть нехватку» не показываются), «В копилку» или «Не хватает», затем «по истории потрачено» за дни периода, «баланс» = поступления − потрачено без переноса и «в копилке» на конец периода.

В «Истории трат» сверху форма добавления траты, под ней «Итого за всё время», дальше месяцы от старых к новым; месяц сворачивается, прошедшие свёрнуты по умолчанию, итог месяца — в заголовке. Внутреннего скролла нет.

Вкладки: «Каждый день» — `#today`, `#hist`, `#shop`, `#wish`; «Долгосрок» — `#next`, `#cfg` «Настройки», `#xin` «Поступления», `#debts` «Обязательные платежи», `#plan`.

## Дизайн

- Подложка только у сворачиваемых блоков (`.panel`); внутри — разделители, без вложенных плашек.
- «Траты на жизнь»: плитка периода — потрачено крупно (красным, если больше нормы на сегодня = прошедшие дни периода × `limit`), мелко — лимит периода «из N €»; норма на экране не выводится.
- «Детализация периода»: под суммой поступления синяя подпись «поступит <дата> · через N дн.». «Обязательные траты» — итог и под ним напоминание: дата, название, сумма, оплаченные платежи зачёркнуты. Затем «Жизнь N дней».
- Хотелки: галочка «купила», цена 0 € вместо «даром»; галочка недоступна, пока хотелка не по карману.
- Удаление строк — × с подтверждением.

## Проверка перед коммитом

Открыть `index.html` в браузере шириной 390 px: нет ошибок в консоли, пустой шаблон открывается без данных, настройки и новая трата переживают перезагрузку, таблицы не вылезают за экран.
