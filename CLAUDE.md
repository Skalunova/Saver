# Планирование бюджета

Личный бюджет-трекер Полины: дневной лимит на жизнь, история трат, хотелки, список покупок и долгосрочный план накоплений в евро. Одна страница, открывается с телефона как ярлык на домашнем экране.

- Сайт: https://skalunova.github.io/Saver/me/ — эта ветка `me`. По адресу https://skalunova.github.io/Saver/ — пустой шаблон из `main`.
- Ветки: `me` — версия Полины с её планом и данными; `main` — шаблон с настройками в интерфейсе, без личных данных. Правки для Полины — в `me`; в `main` только то, что нужно шаблону. Кнопка «Бэкап» есть только в `me`.
- Деплой: `.github/workflows/pages.yml` (одинаковый в обеих ветках). Пуш в `main` собирает сайт из обеих веток; пуш в `me` перезапускает эту сборку на `main`. В настройках Pages источник — GitHub Actions.
- Раньше в этом репозитории жила «Кубышка» (трекер накоплений в рублях, localStorage `kubyshka_v2`). Она заменена этой страницей; её 24 хотелки перенесены в евро.

## Как работать

- Отвечать по-русски, начинать с «Полина, …». Только суть: без вступлений и без предложений помощи в конце.
- Уточняющий вопрос — только как весь ответ целиком, не довеском к готовому.
- Простое решение для простой задачи. Никаких фреймворков, сборки, бэкенда без прямой просьбы.
- Не трогать несвязанный код; замеченные проблемы называть отдельной строкой с файлом и местом.
- Неуверенность называть прямо. Компромиссы — коротко: что получаем, чем платим.
- Тексты в интерфейсе — инфостиль, 1–2 слова в названиях, суммы только в евро.

## Файлы

- `index.html` — вся страница: разметка, стили, шим хранилища, основной IIFE-скрипт и скрипт бэкапа. Шрифт Roboto с Google Fonts.
- `data.json` — последний бэкап базы, публикуется рядом со страницей. Обновляется кнопкой «Бэкап».
- `CLAUDE.md` — этот файл.

## Хранилище

Страница написана под базу артефакта Claude (`window.claude.use('db')`). В этой версии перед основным скриптом стоит шим с тем же интерфейсом поверх `localStorage`:

- ключ `budget-db-v1` — вся база одним JSON;
- при первом открытии (ключа нет) база берётся из `data.json` рядом со страницей, без сети — из константы `SEED` в шиме (снимок на 06.10.2026);
- дополнения: в `data.json` может лежать `patches: [{id, spend: {день: [{a, n}]}, extra: {id: …}, shop: {id: …}}]` — записи, внесённые не с телефона (например, по выписке). При каждом открытии шим применяет ещё не применённые (id в `saver-patches`): трату — если суммы ещё нет среди записей этого дня, поступление и пункт списка покупок — если такого id нет. Перед «Бэкапом» страницу нужно открыть, иначе бэкап сотрёт `patches`;
- интерфейс: `db.doc('коллекция/id').set|update|delete`, `db.collection('имя').onSnapshot(cb)`, где `cb` получает `{docs:[{id, data()}]}`.

Следствия: данные живут в одном браузере, между устройствами не синхронизируются; очистка данных сайта возвращает последний бэкап из `data.json`. Изменение `SEED` не доходит до тех, у кого база уже создана, — для этого нужна смена ключа или миграция.

Прочие ключи `localStorage`: `kopilka-done` (галочки старого графика, больше не используются), `kopilka-fold2` (свёрнутые блоки), `kopilka-tab` (открытая вкладка), `saver-gh-token` (токен GitHub для бэкапа), `saver-backup-at` (время последнего бэкапа), `saver-patches` (применённые дополнения).

Шаблон из `main` живёт на том же домене и использует свои ключи (`saver-db-v1` и др.), поэтому базу Полины не видит.

### Бэкап

Кнопка «Бэкап» в подвале страницы (видна на обеих вкладках) коммитит базу из `budget-db-v1` в `data.json` ветки `me` через GitHub API. Токен — fine-grained, только репозиторий `Skalunova/Saver`, Contents: read and write; вводится один раз и хранится в `localStorage`. При ответе 401/403 токен стирается и запрашивается заново. Если данные не изменились, коммита нет.

### Коллекции

| Коллекция | id | Поля |
|---|---|---|
| `spend` | `YYYY-MM-DD` | `amount` — сумма за день, `items: [{a, n}]` — сумма и пометка |
| `wishes` | `b01…b24` из Кубышки, `c<timestamp>` новые | `name`, `price`, `done`, `day` — дата покупки; появляется при отметке, `null` после снятия, в `SEED` нет |
| `extra` | `x<timestamp>` новые, `x20260928a`, `x20260928b` в `SEED` | `date`, `amount`, `cur: 'RUB'\|'EUR'`, `note`, `life` — галочка «на жизнь» (нет у старых записей = без галочки), `kind: ''\|'sal'\|'adv'\|'bal'` — доп. деньги, факт зарплаты или аванса, корректировка «на счету» (`x20260928a` без поля считается авансом); у `bal` ещё `sp`, `paid` (снимок) и `calc` — расчёт на момент корректировки (у старых сверок нет) |
| `paid` | `data-p` строки долга (`done`; `del: true` — строка удалена: скрыта в таблице и истории, её платёж убран из плана, сумма вернулась в копилку): `fee-260925`, `friend-260928`, `dorm-261005`, `dep-261005`, `d3-261005`, `d3-261105`, `d3-261205`, `olya-261205`, `fee-270205`, `fee-270805`, `fee-280205` | `done` |
| `debts` | `c<timestamp>` | `name`, `amount` — строка из поля ввода, не число (в план идёт через `money()`, рубли по `RUB`), `date`, `done` — платежи, добавленные вручную |
| `shop` | `s<timestamp>` | `name`, `done`, `t` |
| `save` | `v<timestamp>` | `date`, `amount` — перевод с расчётного счёта в копилку; с минусом — взяла из копилки (в графике «неопознанный расход из сбережений») |

Дата в id `paid` не всегда равна дате платежа: `d3-261005` — платёж 13.11 (долг сдвинут на месяц: 13.11, 13.12, 13.01.27), `fee-270205` — 13.02.27, `dorm-261005` оплачен 28.09. Название, сумма и дата платежа — в массиве `PAYS` в скрипте; из него рисуется таблица (`data-d` строки — дата платежа) и строится план. Дата платежа — по ней оплаченная строка попадает в историю трат. Id не переименовывать: по ним хранятся галочки, после переименования они сбросятся.

## Структура страницы

Две вкладки, переключение через `main[data-tab]` и `section[data-tab]`.

- **Каждый день:** `#today` «Траты на жизнь» (счётчик и плитки), `#hist` «История трат», `#shop` «Список покупок» (свёрнут), `#wish` «Хотелки» (свёрнут).

В «Истории трат» сверху форма добавления траты (`#bf`), под ней «Итого за всё время», дальше месяцы от старых к новым. Месяц — сворачиваемая группа с итогом в заголовке; прошедшие месяцы свёрнуты, текущий и будущие раскрыты, ручное раскрытие помнится до перезагрузки (`mOpen`). Внутреннего скролла у блока нет.
- **Долгосрок:** `#sav` «Накопления» (главный цветной блок), `#xin` «Поступления», `#debts` «Обязательные платежи», `#plan` «График по датам», `#acc` «На счету». Блока «Детализация периода» больше нет (убран 23.10.2026).

Блоки сворачиваются по заголовку (`.tg`, класс `collapsed`, умолчание из `data-closed`).

Основные функции: `build()` — собирает события плана; `acct()` — деньги на счету; `renderPlan()` (в конце вызывает `renderSav()` и `renderAcc()`), `renderBud()`, `renderWishes()`; `addSpend(day, delta, note)`.

## Логика плана

Константы в скрипте:

- `L = 23` — лимит на жизнь, €/день.
- `RUB = 105.5` — курс для доп. поступлений в рублях; плановая зарплата посчитана по 105.
- `START = 22.09.2026`.
- `COVER = 122` — покрытый перерасход, прибавляется к доступному.
- `MOVE = {'2026-10-02': 589, '2026-10-05': 89}` — покупки для переезда, идут в историю, но не в дневной лимит.

Ритм поступлений:

- **До 15.11.2026 — работа в России.** 13-е — зарплата, плановая 1545 €: долги и взносы, жизнь на 15 дней (345 €), остаток в копилку. 28-е — аванс 1264 €: аренда 337 € и связь 20 € (обе — платежи 1-го следующего месяца), медстраховка 140 €, жизнь до 13-го, остаток в копилку. Последние: аванс 28.10, зарплата 13.11, 15.11 — премия за квартал 1686 € и расчёт за 1–15.11 ≈ 1264 € (сумма — допущение).
- **С 16.11.2026 — немецкая компания, неполный день, ≈ 1370 € в месяц** до конца плана. Зарплата в плане 28-го (дата — допущение), за ноябрь половина — 685 €. С декабря один период в месяц: 28-го зарплата → аренда 337 € и связь 20 € (1-го), медстраховка 140 €, жизнь до 27-го следующего месяца (дни × `L`), остаток в копилку. Связь €20 отдельным платежом с 1.11.2026 (сумма от Полины, дата 1-е — допущение).
- **Блок-счёт** — 21.10.2026 пришёл двойной платёж за сентябрь и октябрь, 1984 €; дальше по 992 € 26-го с 26.11.2026 по 26.08.2027 (12 месяцев всего — допущение, не подтверждено).
- **Аренда** — 337 € с 1.11.2026 (была 330 €).
- **Медстраховка** — 140 € в месяц с октября 2026: за октябрь — из зарплаты 13.10 (уже учтена сверкой 21.10), дальше — из аванса 28.10 и немецких зарплат.
- **Премия** — только 15.11.2026 (последняя, за квартал); 15.10.2026 не пришла.

Факт зарплаты или аванса вводится в «Поступлениях» (выбор «зарплата» / «аванс») и заменяет плановую сумму ближайшего по дате поступления того же вида; несколько записей складываются. Остаток прошлых денег (`carry`: 316 € у 13.10, обнулён корректировкой) входит в поступление и фактом не заменяется. У 25.09 — стартовый баланс 1044 €: в графике это доход первого периода (раньше был вписан остатком 624 € в 28.09).

Все обязательные платежи — из `PAYS` (таблица) и добавленные вручную (`debts`) — идут в план одинаково: списываются с последнего поступления «на жизнь» (или стартового баланса 25.09) не позже своей даты (раньше первого — с первого). Рубли — по `RUB`. Отметка «оплачено» на план не влияет, удаление (`del`) убирает платёж из плана. Если ему не хватает, нехватку закрывают поступления без жизни в том же периоде (блок-счёт, премия) — строкой «закрыть нехватку», как доп. поступления.

Долги и взносы (`PAYS`): долг 150 000 ₽ частями по 50 000 ₽ 13.11, 13.12, 13.01.27 (≈474 € каждый; в октябре не платится); Оле 175 € — 13.12; семестровый взнос 400 € — 13.02.27, 13.08.27, 13.02.28.

Два счёта: расчётный (все доходы и расходы) и копилка (сберсчёт), куда Полина переводит вручную. Копилка растёт только переводами из «Накоплений» (`save`).

«На счету» (`#acc`, `acct()`): последняя корректировка (`extra` с `kind:'bal'`, вводится в «На счету», старые сверки тоже) + поступления плана с датой после неё и не позже сегодня (факт или план; в день корректировки считаются уже пришедшими) + доп. деньги после неё − траты истории с её даты (минус `sp`; записи и `MOVE`, включая будущие даты) − платежи − переводы в копилку после неё. Платежи из таблицы и свои — после отметки «оплачено», кроме оплаченных на момент корректировки (`paid`; у старых без снимка — с датой до неё); плановые без отметки (аренда, страховка) — по своей дате. Неоплаченные платежи до следующего поступления «на жизнь», включая просроченные, — «Из них на платежи». В блоке: «По расчёту», «Корректировка dd.mm» (последняя), форма и список только тех корректировок, где была разница. Корректировка запоминает расчёт (`calc`): разница с введённой суммой — «неопознанный доход» или «неопознанный расход» в графике. Корректировка обнуляет вписанный остаток (`carry`) следующего поступления «на жизнь».

Доп. поступление без галочки «на жизнь» сначала закрывает недостачу предыдущего события (`need`), остаток идёт в копилку. С галочкой — целиком идёт в дневной лимит: в плане строка «в лимит на жизнь», в копилку 0, нехватку не закрывает. Строка не начинает новый период (метка не начинается с «на жизнь»).

«Можно сегодня» — от денег на счету, если есть хоть одна корректировка «на счету»: свободно = на счету − платежи до поступления (`acct()`). Можно сегодня = min(`L`, (свободно + потрачено сегодня после корректировки) ÷ дни до поступления) − потрачено сегодня после корректировки: сверх `L` в день — копилка. Лимит на подкове = потрачено за период + деньги на жизнь до поступления (не больше `L` в день). «Можно завтра» = min(`L`, (свободно − «Можно сегодня») ÷ (дни до поступления − 1)) — если сегодня потратить всё разрешённое; перерасход сегодня при деньгах на счету завтрашнюю сумму не уменьшает — он уходит из копилки. В последний день периода и без сверки — по дневному лимиту: доступно − «Можно сегодня» + `L`. Если сегодня 0 и завтра 0, строка «Снова можно с <дата поступления>». Без корректировок — дневной лимит: доступно на сегодня = дни с `START` по сегодня × `L` + `COVER` + поступления «на жизнь» с датой не позже сегодня − все траты, включая записанные на будущие даты.

Лимит периода на подкове «Траты на жизнь» = дни периода × `L` + перенос. Перенос — нарастающий остаток на последний день прошлого периода по той же формуле (дни с `START` до начала периода × `L` + `COVER` + поступления «на жизнь» до начала периода − траты до начала периода); бывает отрицательным. Для первого периода перенос = `COVER`. Поступления «на жизнь» внутри периода с датой не позже сегодня прибавляются к лимиту. Остаток лимита периода = «Можно сегодня» + оставшиеся дни × `L` (если нет трат на даты после периода).

«Ушло за день» (`dayOut()`) — всё, что видно в истории трат: записи `spend`, покупки для переезда `MOVE`, оплаченные строки долгов (рубли переводятся по `RUB`). На этом считаются:

- в истории трат — итог в заголовке каждого месяца и «Итого за всё время» над списком.

График — периоды. Период начинается с поступления, у которого есть строка «на жизнь» (13-е и 28-е), и длится до следующего такого же; поступления без неё (15-е, поступления из `extra`) входят в текущий период, первый период начинается с `START`. Внутри периода — дебет с кредитом: «Доход» (поступления периода с датой, доп. деньги, неопознанный доход), «На жизнь» (у прошедших периодов — «На жизнь, по истории»: записи `spend` за дни периода, без `MOVE` — покупки переезда уже в платежах; у текущего и будущих — дни × `L` и доп. деньги «на жизнь», у текущего ещё строка «потрачено по истории»), «Обязательные платежи» (по своей дате), «Неопознанное» (неопознанный расход по корректировке и минус из копилки), «Отложить» = доход − жизнь − платежи − неопознанное (меньше нуля — «Не хватает», `t-warn`), «Отложено» — переводы в копилку с датой в периоде, «В копилке» — нарастающим итогом: прошедшие периоды по факту, текущий — max(факт, план), будущие — по плану. Строк сверки и «закрыть нехватку» нет. Заголовок — даты, шильдики и «Отложить»; раскрыт только текущий период (`pOpen`).

Плашка периода — только символ: копилка ведётся с первого перевода (`save`), периоды, закончившиеся до него, без плашки и без «Отложено». Цель = max(0, «Отложить»), допуск ±10 % (не меньше €1): в допуске — `t-ok` «✓», больше — `t-ok` «↑», меньше или «Отложить» < 0 — `t-warn` «↓»; у текущего периода «↓» не ставится, пока он не кончился. Итог под графиком «В копилке к <конец плана>» = нарастающий итог последнего периода — он же «из €N» на подкове «Накоплений».

«Накопления» (`#sav`): подкова по центру «Накоплено €X из €N» (сумма переводов из итога плана), строки «На счету сейчас», «План на <период>», «Отложено» с плашкой; форма перевода (сумма, дата, «В копилку») и список переводов с ×.

Контрольные точки (бэкап 23.10.2026, переводов в копилку ещё нет): «Можно сегодня» €23, «На счету сейчас» €1 961, план 13.10–27.10 — отложить €2 055, «В копилке к 27.10.2028» €16 996. После правок плана сверять с ними или объяснять расхождение.

- Трата 01.10 на 155 € остаётся одной строкой без пометок.

## Проверка перед коммитом

Открыть `index.html` в браузере шириной 390 px: нет ошибок в консоли, на «Каждый день» видны счётчик и история, новая запись переживает перезагрузку. Вёрстка проверяется на телефонной ширине — таблицы не должны вылезать за экран.

Репозиторий публичный: суммы, долги и имена видны всем. Новые личные данные в код и `SEED` — только с согласия Полины.

## Дизайн

Дизайн-система v2 (по референсам Cleo, Minna no Ginko, Kit): внедрена на «Каждом дне»; на «Долгосроке» — списки, формы и шильдики по тем же правилам, главный цветной блок — «Накопления» (стили `#today` продублированы для `#sav`, `#vt`, `#vm`, `#vl`; без левой цифры: подкова 200 px по центру, сумма в ней 43).

- Знак валюты всегда перед числом: «€331», «−€155», «из €345», «₽50 000» (`eur()`, `num()`, статичный текст). Новые суммы писать так же.
- Шрифт Golos Text. Роли: `.big-n` — главная сумма экрана 64/800 с единицей 22/700; `.mid-n` — сумма блока 36/800 с единицей 18/600 (формат «331 /345 €»); h1 30/800; h2 20/800; текст 15/400; подпись `.lbl` 14 muted; шильдик `.tag` 12/700. Крупные цифры — плотный трекинг −0.04em, табличные.
- Цвет: тёплый фон `--bg`, белые карточки без рамки (радиус 24), главный блок экрана — цветной `--hero` («Траты на жизнь»). Управление — тёмные пилюли (`--ink`), поля — заливка `--field`. Статус — шильдиками `.tag` (`t-ok` в норме / по карману, `t-warn` выше нормы, `t-grey` нейтрально), а не цветом текста.
- Итоги внутри карточки — строка `.lead`: подпись слева, сумма справа, без точек между ними.
- Дробная часть суммы — через точку: «€2 488.94». В «Итого за всё время» знак € вдвое меньше числа.
- В строках истории дата — отдельная приглушённая колонка (`.hd`), без «·» перед названием. Суммы трат без минуса (плюс — только у возвратов). У каждой строки есть ×: у трат — удалить запись; у «покупок для переезда» — скрыть (`paid/move-YYYY-MM-DD` с `del: true`, строка уходит из истории и итогов); у оплаченного платежа — снять отметку «оплачено» (строка уходит из истории, платёж остаётся в плане). Разделителей между месяцами нет, стрелка месяца — маленькая, после суммы. «Итого за всё время» — под месяцами.
- Шкала отступов `--s1…--s5` = 4 · 8 · 12 · 16 · 24: между элементами блока 16; цифра → подпись 8; инфографика → список 16 + 16; строки списков 8; поля формы друг под другом 12; поле → кнопка в строке 24 (`.frow`).
- Вкладки — переключатель: дорожка-пилюля и тёмный бегунок, который едет за `main[data-tab]`.
- Формы добавления (`.addf`: история трат, список покупок, хотелки) стоят вверху блока: поля с подчёркиванием без заливки, кнопка «Добавить» справа. Форма траты: «сумма» и «на что»; дата — пилюля «сегодня ▾» (`#bdl`), поверх неё прозрачный `input[type=date]` `#bd`; рядом `#bdv` «за день N €», если выбран не сегодняшний день.
- «Траты на жизнь»: два равноценных блока, всё по центру. «Можно» — 76/800, высотой примерно до верхней трети подковы; сумма в подкове — 43/800, под дугой с зазором, не касается её концов. Слева «Можно сегодня, €» и сумма без знака. Справа «Потрачено из €N», сумма в подкове тоже без знака. Нижний край «можно», концы подковы и сумма в подкове — на одной линии (сдвиги `--dy0`, `--dy1` подобраны замером), сумма в подкове сдвинута на 3 px вправо к центру тяжести блока, подписи опущены на 10 px (N — лимит периода), подкова над суммой, заполнена долей потраченного от лимита. Подписи стоят под цифрами. Ниже строки: «Потрачено dd.mm–dd.mm» (период) с шильдиком `t-grey` «N %» — доля потраченного от лимита на подкове (больше 100 % или лимит ≤ 0 — `t-warn` «перерасход», подпись «из −€N»), «Осталось на dd.mm–dd.mm» (лимит на подкове − потрачено за период, округлено до евро, при перерасходе с минусом), «Потрачено сегодня», «Можно завтра», (если сегодня и завтра 0) «Снова можно с …».
- Палитра (выбрана Полиной): светлая — белый, `#EDECF3`, голубой `#B7D8F1` (главный блок), лососевый `#F6A48C` (шильдик-предупреждение), подкова — чёрная, чёрный; тёмная — чёрный, синий `#271358` (главный блок), розовый `#E86C6C` (подкова и предупреждение), `#EDECF3`, белый. Карточки в тёмной — `#111115` (производный оттенок, в палитре его нет). Шильдики: `t-ok`, `t-warn`, `t-grey`. Других цветов нет: старые `--save` и `--pay` («Долгосрок», ошибки, галочки таблиц) равны `--ink`, знак плюс/минус говорит сам.
- Чекбоксы списков — свои (квадрат 24, радиус 8, тёмная заливка при отметке). Хотелка не по карману — серый шильдик и неактивная галочка.
- Токены и роли — в `:root` и блоке «Дизайн-система v2» в конце `<style>`; новых размеров и цветов не заводить.
- Сетка: шаг 4 px. Внутри блока отступ 16, между элементами 12, строки списков 8 по вертикали, вложенные строки сдвинуты на 12.
- Подложка только у сворачиваемых блоков (`.panel`). На «Каждом дне» разделителей нет, кроме линий между месяцами истории. Все блоки по умолчанию свёрнуты (`data-closed`), раскрытия помнятся в `kopilka-fold3`.
- «Траты на жизнь»: плитка периода — потрачено крупно (красным, если больше нормы на сегодня = прошедшие дни периода × `L`), мелко — «из N €».
- «Долгосрок»: без разделителей и без «·» в строках. Строки списков — как в истории трат: дата приглушённой колонкой (`.hd`), что, сумма. Формы «Поступлений» и «Обязательных платежей» — `.addf` вверху блока; дата, валюта и вид поступления — пилюли `.dpill` с прозрачным `input[type=date]` или `select` поверх подписи. Нехватка — шильдик `t-warn`.
- «Обязательные платежи»: форма — название, сумма с пилюлей валюты €/₽ (`#dc`, сохраняется строкой «€175» или «₽50000»), дата. Строки: галочка, название, дата (приглушённо), сумма, ×. Ячейки строки: `cells[1]` название, `[2]` дата, `[3]` сумма, `[4]` × — `dayOut()` берёт сумму из `cells[3]`.
- «График по датам»: год — заголовком (`.yr`, 15/600 приглушённый) перед первым периодом года, в датах периодов года нет. Внизу периода — «По истории потрачено» и «В копилке» отдельными строками. Под всеми периодами — итог «В копилке к <конец плана>» крупно (`.ptot`, как «Итого за всё время» в истории).
- Хотелки: галочка «купила», цена 0 € вместо «даром»; галочка недоступна, пока хотелка не по карману.
- Платёжные строки удаляются через × с подтверждением.
